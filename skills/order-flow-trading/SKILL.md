# 订单流交易（Order Flow）

以独立研究员和交易员身份工作。本 Skill 是读书笔记与方法提炼，概念和规则用自己的话重写，阈值注明出处；不含原书正文和图表。原书作者是期货短线交易员，例子多为日内 5–30 分钟图，用于股票、加密或更长周期时要重新检验。

## 先读什么

- 交易形态和计划：[形态与交易计划](references/setups.md)。
- 关键价位、VWAP、冰山单、图表类型：[价位与背景](references/levels-context.md)。
- 止损、离场、心态：[风控与心态](references/risk-psychology.md)。
- 写代码或做检验：[量化映射与检验](references/quant-mapping.md)，并用 `scripts/footprint.py`。

## 核心思想（一句话版）

K 线只给开高低收；足迹图把每根 K 线拆成每个价位的**主动买量**和**主动卖量**。价格要动，需要主动方持续吃掉挂单；趋势停下来，是因为主动方不愿再追、力气用完，或者被被动方的挂单吸收。读订单流就是在关键价位上判断：**谁在主动、谁在被动、谁被套、谁已经没力气**。

## 工作流程

1. **盘前定位**：按 [关键价位清单](references/levels-context.md#关键价位清单) 标出年、两个月、上月、前两日、昨日的高低收、夜盘高低、昨日价值区间上下沿、当日事件时间。只在这些价位附近重点读足迹。
2. **选图**：作者的顺序是等价图 → 等量图 → 等时图，再看日、周、月线找大级别高低点。日内常用 15–30 分钟时间图；1 分钟太碎，成交量信息不足。
3. **读单根 K 线**：Delta 符号与收盘方向是否一致；POC 在 K 线上、中、下哪里；顶部、底部两档的成交量比（大单 / 微单）；有没有斜对角失衡和三档以上的堆积失衡；极端价位是否有被套交易者。
4. **读连续几根**：吸收（高成交、Delta 接近零、价格横）之后谁先主动出击、突破价值区间；回踩堆积失衡区时主动方是否重新出现。
5. **定交易计划**：入场条件、结构性止损（堆积区外 1–2 跳或信号 K 线极值外）、目标（下一个关键价位或固定跳数）、时间止损。作者要求盈亏比 ≥ 2:1、胜率 ≥ 50%，理想 60%（作者自述，未经审计）。
6. **持仓管理**：入场理由消失就离场，不等止损；出现反向信号（矛盾信号）时重新评估，不因已持仓而忽视。
7. **复盘**：记录信号类型、阈值、背景价位和结果，包括没入场的信号和失败案例。

## 和 3xOrange Advanced System 的关系

- 老王的 MMOF、筹码结构订单流版、流动性热力图 Pro 都用到同一套足迹概念（失衡 300%、价值区 70%、POC、主动买卖）。本 Skill 给出这些概念的出处和可计算定义。
- **已经检验过、没通过的**（见 [量化映射与检验](references/quant-mapping.md#已有检验结果)）：币安日线和小时线的主动买卖差、链上持仓结构、美股 FINRA 场外成交，都没能在事先定的规则下提前找到行情起点。这些都是**K 线级别的汇总量**，不是本书讲的价位级足迹。
- **还没检验的**：价位级足迹信号（被套交易者、大单 / 微单、堆积失衡回踩、订单流背离）。加密可以用币安免费的逐笔成交 aggTrades 构建足迹，见 `scripts/footprint.py`。

## 归属与限制

- 书中的阈值（失衡 3:1、堆积 3 档、大单比 < 0.699、微单比 > 28、价值区 70%）是作者在其 NinjaTrader 插件里的经验设置，不是统计检验结果。作者明确说他不把这套方法程序化，要结合绝对成交量和背景主观判断。
- 胜率、盈亏比都是作者自述。用到本系统前，按 [量化映射与检验](references/quant-mapping.md) 写定规则、只测一次、分时期报告。
- 订单流图只记录已成交的主动单，看不到撤单和未成交挂单；冰山单要盯盘口实时变化，事后从足迹上无法确认。
